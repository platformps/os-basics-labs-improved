About this lab

A process is a program that is running. In this lab you use Process Explorer, a free Microsoft Sysinternals tool, to look at running processes, see which process started which, and look inside a process at its threads and handles. Then you use Registry Editor to change one setting and watch what it does.

Objectives

  • Part 1: Explore processes
  • Part 2: Explore threads and handles
  • Part 3: Explore the Windows Registry

What is different from the original lab: In the real Process Explorer you find a window's process by dragging a crosshair icon onto the window with a mouse. That drag has no keyboard equivalent, so this simulation gives you a Find Window's Process button that lists the open windows instead. Everything else follows the original steps.

Part 1: Explore processes

Step 1: Download the Sysinternals Suite

  1. Open Microsoft Edge from Start.
  2. In the address bar, type learn.microsoft.com/sysinternals/downloads/sysinternals-suite and press Enter. (The original lab gives an older technet address; it now sends you to this page.)
  3. Select Download Sysinternals Suite.
  4. Open File Explorer and go to Downloads. Select SysinternalsSuite.zip, open its Actions, and choose Extract All. Accept the suggested folder.
  5. Leave Microsoft Edge open. You need it in the next step.

Step 2: Explore an active process

  1. In the extracted SysinternalsSuite folder, open procexp64.exe. When the Process Explorer License Agreement appears, choose Agree.
  2. Process Explorer lists every running process as a tree. A process that another process started is shown indented under it, and your screen reader hears "child of" followed by the parent's name.
  3. Choose Find Window's Process and pick the Microsoft Edge window. Process Explorer selects the Edge process, msedge.exe.
  4. With msedge.exe selected, open the Actions for the process and choose Kill Process. Confirm with OK.

What happened to the web browser window when you killed its process?

The Microsoft Edge window closed right away. The window belongs to the process, so ending the process ends the window and its helper processes.

Step 3: Start another process

  1. Open Command Prompt from Start.
  2. Switch back to Process Explorer, choose Find Window's Process, and pick the Command Prompt window. The process is cmd.exe. Its parent is explorer.exe, and it has a child process, conhost.exe (Console Window Host).
  3. Switch to Command Prompt and run ping www.cisco.com. While it runs, switch to Process Explorer and look under cmd.exe. Process Explorer announces new processes as they start.

What happened under cmd.exe while the ping was running?

A new child process, PING.EXE, appeared under cmd.exe while the ping ran, and it disappeared when the ping finished. Each command you run from the prompt is its own process, started by cmd.exe.

  1. Suppose you suspect conhost.exe could be malware pretending to be a Windows file. Select conhost.exe, open its Actions, and choose Check VirusTotal. Agree to the VirusTotal terms when asked.
  2. A VirusTotal column appears. Select the result for conhost.exe to open the report in Microsoft Edge.
  3. In Process Explorer, select cmd.exe and choose Kill Process.

What happened to the child process conhost.exe when you killed cmd.exe?

conhost.exe ended too. Console Window Host only exists to draw the console window for cmd.exe, so when its parent ends it has nothing left to do and exits. (Not every child process ends with its parent, but this one does.)

Part 2: Explore threads and handles

A process has one or more threads; a thread is the part of a process that the processor actually runs. A handle is a reference a process holds to something the operating system manages, such as a file, a registry key, or another thread.

Step 1: Explore threads

  1. Open a new Command Prompt. This starts a new cmd.exe and conhost.exe.
  2. In Process Explorer, select conhost.exe, open its Actions, and choose Properties. Go to the Threads tab.

What information does the Threads tab show? What other kinds of information are on the other tabs of the Properties window?

The Threads tab lists each thread with its thread ID (TID), CPU use, cycles delta, and start address, plus the total thread count. The other tabs show the image path and command line, performance information, network connections, security information (user and groups), environment variables, and readable strings found in the file.

Step 2: Explore handles

  1. Close the Properties window. With conhost.exe still selected, open the View menu, choose Lower Pane View, then Handles. A Handles table appears under the process list.

Examine the handles. What are they pointing to?

The handles point to files and folders (such as \Device\ConDrv and C:\Windows\System32), registry keys, threads, events, ALPC ports, and the window station and desktop the console is drawn on.

  1. Close Process Explorer.

Part 3: Explore the Windows Registry

The Windows Registry is a database of settings for Windows and for apps. Registry Editor shows five root keys at the top level:

  • HKEY_CLASSES_ROOT: file type associations and information about registered app components. It combines settings from HKEY_LOCAL_MACHINE\Software\Classes and HKEY_CURRENT_USER\Software\Classes.
  • HKEY_CURRENT_USER: settings for the user who is signed in right now.
  • HKEY_LOCAL_MACHINE: settings for the computer itself, shared by every user.
  • HKEY_USERS: settings for every user profile loaded on the computer. HKEY_CURRENT_USER is a shortcut to the current user's entry here.
  • HKEY_CURRENT_CONFIG: the hardware profile Windows is using right now.

Keys work like folders. Inside a key are values, and each value has a name, a type, and data.

  1. Open Registry Editor from Start (search for regedit). Choose Yes when User Account Control asks.
  2. When you agreed to the Process Explorer license, it saved that choice in the registry. Go to HKEY_CURRENT_USER\Software\Sysinternals\Process Explorer. You can expand the tree, or type the path in the address box.
  3. In the values list, find EulaAccepted. Its data is 0x00000001 (1), which means the license was accepted.
  4. Open EulaAccepted to modify it, change the value data from 1 to 0, and choose OK. A value of 0 means the license has not been accepted.

What does the Data column show for EulaAccepted now?

0x00000000 (0)

  1. Open Process Explorer again from the SysinternalsSuite folder in File Explorer.

What happened when Process Explorer opened?

The Process Explorer License Agreement appeared again, because Process Explorer reads EulaAccepted when it starts and found 0. Many apps store settings in the registry this way, which is also why attackers and malware often change registry values.

Corrections from the original lab

This version fixes these items from the Cisco lab, so answers here may differ slightly from the original answer key.

  • The original calls EulaAccepted a registry key. It is a registry value inside the Process Explorer key.
  • The original says HKEY_CURRENT_USER holds settings for "the users who are currently logged in." It holds settings for the one user whose session is running.
  • The original's sample answer for the threads question lists other tabs instead of thread details. The new sample answer covers both.
  • The Sysinternals download address in the original is an old technet link; this version uses the current Microsoft Learn address.
  • The crosshair drag in Process Explorer is replaced with a keyboard-friendly list of windows.
