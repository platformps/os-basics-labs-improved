About this lab

Linux keeps almost all of its settings in plain text files, so working with text editors is a core skill. In this lab you use a graphical editor (SciTE) and a command line editor (nano), find the hidden configuration files in your home folder, change how your shell prompt looks, and change a web server's settings.

Objectives

  • Part 2: Command line text editors
  • Part 3: Working with configuration files

This simulation stands in for the Security Workstation virtual machine. You are logged in as analyst; the password for sudo is cyberops. Cisco's errata reports that Part 3 of the original lab cannot be completed on the newer virtual machine. Everything in this version works.

Part 1: Graphical text editors

Text editors are among the oldest kinds of applications. Some have a graphical window, and some work only on the command line. The Security Workstation includes one graphical editor, SciTE. It is small and fast, and it is all you need for this course.

Step 1.1: Open SciTE from the Applications menu

  1. Choose Applications on the dock, search for SciTE, and open SciTE text editor.
  2. In the editing area, type this sentence on one line, without pressing Enter: Linux treats almost everything as a file, so a text editor is one of the most useful tools a security analyst can learn to use well.
  3. Open the File menu and choose Save. SciTE suggests your home folder, /home/analyst. Name the file space.txt and choose Save.
  4. Close SciTE, then open it again from Applications.
  5. Open the File menu and choose Open. Look for space.txt.

Could you find space.txt right away?

No. SciTE is looking in the right folder, /home/analyst, but its Open dialog starts with the All Source filter, which shows only file types it knows, such as program code. .txt is not one of them.

  1. Change Files of type to All Files (*). Select space.txt and open it. Linux does not need file extensions, but some applications, like SciTE, use them to decide what to show.
  2. Close SciTE.

Step 1.2: Open SciTE from the terminal

  1. Open Terminal from Applications. Run ls. space.txt is in your current folder, so you can open it without a path.
  2. Run scite space.txt. SciTE opens with the file loaded.
  3. Switch back to the terminal window.

Why does the terminal not show a prompt while SciTE is open?

The terminal is busy running SciTE, so it cannot take new commands until SciTE closes.

  1. Close this SciTE window, or press Stop command (Ctrl+C) in the terminal to end it. The prompt returns. Starting SciTE from a terminal is also how you run it as root: sudo scite.

Part 2: Command line text editors

Step 2.1: Command line text editors

Command line editors matter because you often manage a Linux server from a remote text-only session, such as SSH, where there is no graphical desktop. This course uses nano. Another very popular editor is vi (and its improved version, vim), which is powerful but harder to learn.

nano is controlled with the keyboard. Its shortcut list appears at the bottom of the screen: the caret symbol (^) means Ctrl, and M- means the Meta key, which is usually Alt. In this simulation the same shortcuts are also buttons, and nano's function key alternatives work too: F1 Help, F2 Exit, F3 Write Out, and F6 Where Is.

Do not press Ctrl+W in a web browser: it closes the browser tab. Use F6 or the Where Is button instead.

  1. In the terminal, run nano space.txt. nano opens with your sentence.
  2. Your sentence is one long line, longer than nano's 80 column screen. nano does not wrap it; it marks the edge of the screen instead. Choose Read this line as the 80 column screen shows it to hear what the screen row shows.

What character does nano use to show that a line continues past the edge of the screen?

The greater than sign (>). Older versions of nano use a dollar sign ($).

  1. Open nano's help with Ctrl+G (or F1). Leave the help with Ctrl+X (or F2).
  2. Press Ctrl+X to exit nano. If you changed anything, nano asks whether to save: press Y to save or N to discard, then Enter to keep the file name.

Part 3: Working with configuration files

In Linux, the system and its services are configured through files. Configuration files are usually text, and each application or service reads its own files when it starts.

Step 3.1: Locate configuration files

By convention, settings for your own applications live in hidden files in your home folder, and settings for system-wide services live in /etc.

  1. Run ls -l. None of the files look like configuration files.
  2. Run ls -la. The -a option also shows hidden files, whose names start with a dot.
  3. Run cat .bashrc. This file sets up your terminal. The PS1 line defines the prompt: [user@host folder] then a dollar sign, in green (color code 32). The alias lines create shortcuts: when you type ls, the shell runs ls --color.
  4. Run ls /etc, then cat /etc/bash.bashrc. This file sets the default shell behavior for every user. Only root can change files in /etc.

Why are your own application settings stored in your home folder instead of in /etc?

Regular users cannot write to /etc. Linux is a multi-user system, so keeping each user's settings in their own home folder lets every user customize their own applications without changing anything for anyone else.

Step 3.2: Edit and save configuration files

  1. Open SciTE from Applications. Open the File menu, choose Open, set Files of type to All Files (*), and open .bashrc.
  2. On the PS1 line, change 32 to 31. 32 is the color code for green and 31 is red. Save with Ctrl+S and close SciTE.
  3. Open a new Terminal window from Applications. Each terminal window shows its prompt color in the line above the command area.

Did the terminal window that was already open change to red too? Explain.

No. .bashrc is read when a terminal starts, so terminals that were already open keep their old settings. Only new terminals show the red prompt.

  1. Now make the same kind of change on the command line. In the new terminal, run nano .bashrc.
  2. Change 31 to 33 (yellow). Press Ctrl+X, then Y to save, then Enter to keep the name .bashrc.
  3. Run bash to start a new shell that reads .bashrc again. The prompt is now yellow.

Step 3.3: Edit configuration files for services

nginx is a lightweight web server installed on this workstation. Its configuration files are in /etc/nginx. You will change two settings in the file custom_server.conf: the port nginx listens on and the folder it serves web pages from.

  1. Run sudo nano -l /etc/nginx/custom_server.conf. The -l option turns on line numbers. Enter the password cyberops when asked.
  2. Go to line 39 with Alt+G (Go To Line) and change the port from 81 to 8080.
  3. Go to line 47 and change the path /usr/share/nginx/html to /usr/share/nginx/html/text_ed_lab. Keep the semicolon at the end of the line, or nginx will report an error.
  4. Press Ctrl+X, then Y, then Enter to save with the same name.
  5. Run sudo nginx -c custom_server.conf to start nginx with this file.
  6. Open Firefox from Applications and go to 127.0.0.1:8080. A page for this lab appears.
  7. Switch back to the terminal and read the message nginx printed there.

What is the error message in the terminal about?

Firefox also asked for the site's icon, favicon.ico. That file does not exist in /usr/share/nginx/html/text_ed_lab, so nginx logged a "No such file or directory" error. The page itself loaded fine.

  1. Stop nginx with sudo pkill nginx.
  2. In Firefox, reload the page.

Does the web page appear now?

No. Firefox cannot connect, because no web server is listening on port 8080 anymore.

Challenge

Can you edit /etc/nginx/custom_server.conf with SciTE? Describe how.

Yes, but SciTE must run as root because the file is in /etc. From a terminal, run sudo scite /etc/nginx/custom_server.conf. If you open it from the Applications menu instead, SciTE can open the file but cannot save it.

Reflection

  • Each service has its own configuration options, file locations, and syntax. Always check the documentation.
  • Wrong permissions are a very common cause of problems. Make sure you have the right permissions before you edit configuration files.
  • Most services must be restarted before a configuration change takes effect.
