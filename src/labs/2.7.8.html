About this lab

In this lab you update a Windows computer and a Linux virtual machine, tighten Windows password and sign-in rules, open the Windows firewall for ping in a controlled way, and install two Linux security tools.

Objectives

  • Part 1: Update Windows and Linux
  • Part 2: Windows Local Security Policy
  • Part 3: Configure firewall rules
  • Part 4: Install and run applications

The simulation is a Windows 11 PC (signed in as CyberOpsUser, an administrator) with VirtualBox and the CSE-LABVM already imported. Inside the CSE-LABVM you are user cisco; the sudo password is password. The current Windows password is Cisco123!. Nothing you change here touches your real computer.

Part 1: Update Windows and Linux

New flaws are found all the time. Keeping systems up to date closes known holes before attackers can use them.

Step 1: Verify connectivity between the CSE-LABVM and Windows

You need internet access to download updates, and the two computers must reach each other for Part 3.

  1. Open Oracle VirtualBox from Start. Before starting the CSE-LABVM, select it and choose Settings. In the Network section, set Adapter 1 Attached to to Bridged Adapter, then choose the host adapter that connects Windows to the network. Many computers have two: one wireless and one wired. (Tip: ipconfig /all in a Windows Command Prompt shows which adapter has an address.)
  2. Start the CSE-LABVM. Its window opens with a terminal.
  3. In the CSE-LABVM terminal, run ip address to find its IP address.
  4. On Windows, open Command Prompt and run ipconfig to find its IP address.

Record the IP addresses of the CSE-LABVM and the Windows PC. What do they have in common?

In this simulation the CSE-LABVM is 192.168.1.31/24 and Windows is 192.168.1.15/24. On a real network your addresses vary, but both should be in the same network, here 192.168.1.0/24.

  1. From each computer, ping a website of your choice, such as ping www.cisco.com, to confirm internet access. On Linux, ping keeps going until you stop it with Ctrl+C or the Stop command button. You can also limit it, for example ping -c 4 www.cisco.com.
  2. From Windows, ping the CSE-LABVM's address.
  3. From the CSE-LABVM, ping the Windows address. This usually fails because the Windows firewall blocks incoming ping by default. You will add a rule for it in Part 3. Stop the ping with Ctrl+C.

Step 2: Check for Windows updates

  1. From Start, search for check for updates and open Windows Update.
  2. Choose Check for updates, then explore the other options: pause updates, update history, and advanced options.

When did the system last check for updates?

Answers vary. On a real PC it is usually within the last few days; in the simulation it is the time shown under "Last checked."

What are the current active hours? What will Windows do outside them?

Answers vary; in the simulation they are 8:00 AM to 5:00 PM. Windows will not restart the device to finish updates during active hours. Outside active hours it can restart automatically.

Step 3: Update and upgrade Linux

  1. In the CSE-LABVM terminal, run apt-get by itself to see its commands. Always run update before upgrade.
  2. Run sudo apt-get update to refresh the list of available packages. Enter password when asked.
  3. Run sudo apt-get upgrade to download and install newer versions of installed packages. It never removes packages. Answer y when asked to continue.

Part 2: Windows Local Security Policy

Local Security Policy holds the security rules for one computer. You will set the password policy, the account lockout policy, and look at the audit policy.

On a real PC, Local Security Policy comes only with Windows Pro, Enterprise, and Education. On Windows Home, or on a PC you are not allowed to change, read this part and move on to Part 3. The simulation includes it so every learner can practice.

Step 1: Configure the password policy

Your organization's password rules are:

  • A user must use at least 2 different passwords before reusing an old one.
  • Passwords must be at least 8 characters.
  • Passwords must be changed every 90 days.
  • A password can be changed at most once a day.
  • Passwords must be complex: mix lowercase letters, uppercase letters, numbers, and symbols.
  1. Open Control Panel, then Windows Tools (called Administrative Tools in Windows 10), then Local Security Policy. You can also search Start for secpol.msc. Choose Yes in User Account Control.

List a few of the security settings areas in the left pane.

Account Policies, Local Policies, Windows Defender Firewall with Advanced Security, Network List Manager Policies, Public Key Policies, Software Restriction Policies, Application Control Policies, IP Security Policies on Local Computer, and Advanced Audit Policy Configuration.

  1. Expand Account Policies and choose Password Policy. The list shows each policy with its current setting.
  2. Open Enforce password history (press Enter on it, or choose Properties) and set it to 2.
  3. Decide the value for each remaining policy, then set them all.

What values did you set for Enforce password history, Maximum password age, Minimum password age, Minimum password length, Password must meet complexity requirements, and Store passwords using reversible encryption?

Enforce password history: 2 passwords remembered. Maximum password age: 90 days. Minimum password age: 1 day. Minimum password length: 8 characters. Password must meet complexity requirements: Enabled. Store passwords using reversible encryption: Disabled.

Keep Store passwords using reversible encryption disabled. Reversible encryption is close to storing passwords in plain text, so turn it on only when an application truly requires it.

Step 2: Test the password policy

  1. From Start, search for change your password.
  2. Under Password, choose Change, enter the current password, and choose Next.
  3. Enter a new password that breaks the rules (for example, too short or all lowercase) twice, add a hint, and choose Next. Windows refuses it. Choose Cancel or try a password that meets the rules.

What does Windows say when the new password breaks the policy?

The password you entered doesn't meet the password policy requirements. Try one that's longer or more complex.

Step 3: Configure the account lockout policy

  1. Back in Local Security Policy, choose Account Lockout Policy under Account Policies.
  2. Set Account lockout threshold to 5 invalid sign-in attempts.
  3. Make sure Reset account lockout counter after is 10 minutes, and Account lockout duration is 10 minutes.

After an account is locked, how long must the user wait before trying to sign in again?

10 minutes, the account lockout duration.

How many attempts does a user get before the account is locked?

5 attempts.

Step 4: Review the audit policy

  1. Expand Local Policies and choose Audit Policy.
  2. Open Audit account logon events. On the Local Security Setting tab, notice the Success and Failure check boxes.
  3. Choose the Explain tab to read what the setting does, then choose OK.
  4. Review the other audit settings and their Explain tabs.

Part 3: Configure firewall rules

Traffic enters and leaves a computer through ports. A firewall works like a security guard that checks traffic against its rules.

Step 1: Investigate Windows Defender Firewall

  1. From Start, search for and open Windows Defender Firewall. It is on by default.

On a PC managed by an organization, you may see "For your security, some settings are managed by your system administrator."

What are the benefits of Windows Defender Firewall?

It helps stop attackers and malicious software from reaching the computer through the internet or the local network.

  1. Choose Allow an app or feature through Windows Defender Firewall. Apps and features with Yes for a network type are allowed through. Choose Cancel when done.

Describe a negative consequence of having too many exceptions.

Each exception is a hole in the firewall. Attackers scan for computers with many open ports and allowed programs, and every extra exception gives them another way in.

Step 2: Allow echo requests with an inbound rule

On a work computer, your organization may not allow this step. In the simulation it is safe.

  1. In Windows Defender Firewall, choose Advanced settings and choose Yes in User Account Control.
  2. Choose Inbound Rules, then New Rule.
  3. In the New Inbound Rule Wizard, choose Custom and go Next twice, to the Protocol and Ports step.
  4. Set Protocol type to ICMPv4 and choose Customize. Choose Specific ICMP types, check Echo Request, and choose OK.
  5. Go Next three times, to the Profile step. Clear Public so the PC does not answer ping on public networks such as a coffee shop.
  6. Give the rule a descriptive name, such as Allow ICMPv4 Echo Request, and choose Finish. The rule appears at the top of Inbound Rules.
  7. From the CSE-LABVM, ping Windows again. This time you get replies.

Part 4: Install and run applications

You will install two tools on the CSE-LABVM: chkrootkit, from Ubuntu's own software repository, and Lynis, from a repository run by its maker, CISOfy.

Step 1: Install and run chkrootkit

chkrootkit looks for signs of a rootkit: malware that hides itself on a system while giving an attacker control.

  1. Run sudo apt install chkrootkit.
  2. Run sudo chkrootkit to check the system.
  3. The output is long. Filter it for worms with grep; the -i option ignores upper and lower case: sudo chkrootkit | grep -i worm.

Did chkrootkit find any worms? What is the last line that starts with an exclamation point?

No; every worm check says "nothing found." The last line lists the grep command itself. chkrootkit's chkutmp check reports processes that have a terminal but no sign-in record, and grep, running in a pipe, is one of them. It is not a sign of infection.

Step 2: Install Lynis

Lynis is a security auditing tool for Linux and macOS, made by CISOfy. You will use it to harden a system in a later activity. To get the newest version, add CISOfy's repository, and its signing key so apt can verify downloads.

  1. Import CISOfy's signing key. Type it as one line: 
    sudo apt-key adv --keyserver keyserver.ubuntu.com --recv-keys 013baa07180c50a7101097ef9de922f1c2fde6c4
  2. Add the Lynis repository. Again, one line: 
    echo 'deb https://packages.cisofy.com/community/lynis/deb/ stable main' | sudo tee /etc/apt/sources.list.d/cisofy-lynis.list
  3. Refresh the package lists after adding a repository: sudo apt-get update.
  4. Install Lynis: sudo apt install lynis.

Newer method. apt-key works on this Ubuntu 20.04 virtual machine, but it is deprecated and removed in newer Ubuntu and Debian releases. There, save the key to its own keyring file and point the repository at it. The simulation accepts both methods:

curl -fsSL https://packages.cisofy.com/keys/cisofy-software-public.key | sudo gpg --dearmor -o /usr/share/keyrings/cisofy-archive-keyring.gpg
echo 'deb [signed-by=/usr/share/keyrings/cisofy-archive-keyring.gpg] https://packages.cisofy.com/community/lynis/deb/ stable main' | sudo tee /etc/apt/sources.list.d/cisofy-lynis.list

According to the install output, which version of Lynis was installed?

3.0.6 (package 3.0.6-100) in the simulation, the version current when the lab was written. If you see 2.6.2, apt installed Ubuntu's older copy because the CISOfy repository was not added, or apt-get update was not run after adding it.

  1. Confirm the version: lynis show version.
  2. See which versions each repository offers: apt-cache policy lynis. The installed version is marked with three asterisks.

You can run sudo apt-get update and sudo apt-get upgrade again at any time to pick up the latest CISOfy releases.

Corrections from the original lab

  • The Module 2 slide describes a different version of this lab (restore points, UFW, and disabling services). This simulation follows the lab as written: updates, Local Security Policy, the firewall, chkrootkit, and Lynis.
  • The note about Windows Home ends mid-sentence ("read through this part and"). It is completed here.
  • The lockout step sets only the threshold and the reset counter, then asks how long the user must wait to sign in. That wait is the account lockout duration, a separate policy. This version names it. Windows 11 also starts with a threshold of 10 and 10 minute timers, and shows a fourth policy, Allow Administrator account lockout.
  • Windows lists eight password policies on current versions, not six; the two extras (Minimum password length audit and Relax minimum password length limits) are left as they are.
  • The lab says a complex password must contain all four kinds of characters. Windows actually requires three of the four, at least 6 characters, and no use of the account name.
  • The answer key lists Public Key Policies twice.
  • The apt-key and tee commands are split across two lines, so pasting them fails. They are shown on one line here.
  • apt-key is deprecated and removed in newer Ubuntu and Debian releases. The keyring method is added.
  • The original page drops the e-mail address from the gpg output because it is written like an HTML tag. The simulation shows it.
  • One worm name in chkrootkit's output contains a profanity. The simulation masks it.
  • The text prints the grep option -i with a long dash, and has the typos "lookout counter" and "For you security."
