About this lab

Servers are programs that wait for requests and answer them. Clients, which are also programs, send those requests. In this lab you use the Linux command line to find out which servers are running on a computer, which network ports they are listening on, and what they really are.

Objectives

  • Part 1: Servers
  • Part 2: Using Telnet to test TCP services

This simulation stands in for the Security Workstation virtual machine. You are logged in as analyst; the sudo password is cyberops. The process IDs (PIDs) in this simulation match the ones in the original lab, but on a real computer they are different every time.

Part 1: Servers

Step 1: Access the command line

  1. Open Terminal from the Applications button on the dock.

Step 2: Display the services that are running

Many programs run in the background, so users may not notice them. In Linux, running programs are called processes.

  1. Run sudo ps -elf to list every process. Enter the password cyberops when asked. The output is long; open its Table view to move through it by row and column.

Why does the lab run ps as root (with sudo)?

Running as root guarantees you see every process and all of its details. On most Linux systems ps -elf lists all processes even for a regular user, but some systems are set up to hide other users' processes, and some tools (such as netstat -p, later in this lab) only show full details to root.

Programs can start other programs. ps can show this as a tree.

  1. Start the nginx web server: run sudo /usr/sbin/nginx.
  2. Run sudo ps -ejH to show the process tree. In the Table view, each process shows its level in the tree; a process at level 2 was started by the level 1 process above it.

How does ps show the process hierarchy?

With indentation: each child process is indented under the process that started it. In the simulation's table view, the level number gives the same information.

The task a server performs is called a service; a web server provides web services. netstat shows network connections and the servers waiting for them.

  1. Run netstat with no options. It shows a lot of information.
  2. Run man netstat and read about the -t, -u, -n, -a, and -p options.
  3. Run sudo netstat -tunap. Options can be grouped after one hyphen.

What do the -t, -u, -n, -a, and -p options of netstat mean?

-t shows TCP connections, -u shows UDP connections, -n shows numbers instead of names (no DNS, port, or user name lookups), -a shows both listening and non-listening sockets, and -p shows the PID and name of the program that owns each connection.

Does the order of the options matter to netstat?

No. -tunap and -patun give the same result.

Useful columns in the netstat -tunap output:

  • Proto (first column): the Layer 4 protocol, TCP or UDP.
  • Local Address (fourth column): the IP address and port where the server can be reached. 0.0.0.0 means the server listens on every IP address of the computer.
  • Foreign Address (fifth column): the address and port of the other end. 0.0.0.0:* means nothing is connected yet.
  • State (sixth column): the state of the connection, such as LISTEN.
  • PID/Program name (seventh column): the process ID and a short name of the program that owns the connection.

In the netstat -tunap output, what are the Layer 4 protocol, the state, and the PID of the process on port 80?

TCP, LISTEN, and PID 395.

Port numbers are only a convention, but what kind of service usually runs on TCP port 80?

A web server (HTTP).

You can match netstat's output to ps. The process with PID 395 owns TCP port 80.

  1. Run sudo ps -elf | grep 395. The pipe (|) sends the output of ps into grep, which keeps only the lines that contain 395. If your nginx PID is different, use your number.

The process with PID 395 is nginx. How can you tell from the output?

The last column (CMD) of its line shows the nginx command line: nginx: master process /usr/sbin/nginx.

What is nginx, and what does it do?

nginx is a lightweight, high-performance web server, which can also work as a reverse proxy. Searching the web for an unknown process name is a quick way to learn what it is.

The second line shows process 396, owned by the user http, with 395 as its parent. What does that mean, and is it normal?

Yes, it is normal. The nginx master process runs as root so it can open port 80 and read its configuration, then starts worker processes that run as the less privileged http user. The workers handle the client requests. nginx starts a fixed number of workers (here one); it does not start a new process for every client.

Why does the last line show grep 395?

grep 395 was itself running while ps took its snapshot, and its own command line contains 395, so it matches.

Part 2: Using Telnet to test TCP services

Telnet is a simple remote shell. It sends everything, including passwords, as clear text, so it should not be used for remote management; use SSH instead. But it is handy for checking what a TCP service really is, because you can connect to any port and talk to the server directly.

nginx is listening on port 80. What if an attacker named a malware program nginx to make it look like the web server? Connect to it and see how it answers.

  1. Run telnet 127.0.0.1 80.
  2. When it says Connected, type a few random letters and press Enter.

Why did the server send its error back as a web page?

nginx is a web server, so it only speaks HTTP. It did not understand the random letters, so it sent an HTTP 400 Bad Request response in the format of a web page.

From that one reply you learned that the process on port 80 really is a web server, that it is nginx version 1.16.1, and that the network stack works all the way up to the application layer.

  1. netstat also showed a process on port 22, the usual port for SSH. Run telnet 127.0.0.1 22. The server sends a greeting first. Type some random letters and press Enter.
  2. Run telnet 127.0.0.1 68.

What happens when you connect to port 68? Explain.

The connection is refused. Port 68 is used by the DHCP client over UDP. Telnet only uses TCP, and nothing is listening on TCP port 68.

Reflection

What are the advantages of using netstat?

It shows every connection and listening port on a computer, with addresses, ports, and the processes behind them, which gives an analyst a quick overview of what is talking on the network.

What are the advantages of using Telnet? Is it safe?

Telnet lets you connect to any TCP port and see how a service really answers, which helps identify unknown services. It is safe for quick tests like this, but not as a remote shell, because it sends everything, including passwords, unencrypted.

Corrections from the original lab

  • The original prints ps -elf, ps -ejH, -tunap, and several netstat options with a long dash instead of a hyphen. This version uses hyphens.
  • The original's column guide calls Local Address the third column. With Recv-Q and Send-Q, it is the fourth; Foreign Address, State, and PID/Program name are the fifth, sixth, and seventh.
  • The original says "Port 395 is used in this example." 395 is a process ID, not a port.
  • The original says nginx "runs itself for every client that connects." nginx uses a fixed pool of worker processes.
  • The original refers to "the netstat output shown in item (d)," which no longer exists.
  • The original says sudo is needed because other users' processes may not be displayed. On most Linux systems ps shows every process to any user; the sample answer explains when sudo matters.
  • The original's last reflection answer only covers safety; this version also gives the advantages.
