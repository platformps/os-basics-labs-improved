About this lab

Network Mapper, or Nmap, is a free, open-source tool for network discovery and security auditing. It finds which hosts are on a network, which services they run and what versions, which operating systems they use, and whether firewalls filter them. In this lab you use Nmap to find the open ports on your own virtual machine.

This simulation stands in for the CSE-LABVM virtual machine. You are logged in as cisco, and the password for sudo is password.

TCP and UDP ports

Every IP host has two sets of ports, TCP and UDP, numbered 0 to 65,535. A service that waits for connections listens on a port, and the port number identifies the service. The Internet Assigned Numbers Authority (IANA) divides ports into three ranges:

  • Well-known ports: 0 to 1023
  • Registered ports: 1024 to 49,151
  • Dynamic or private ports: 49,152 to 65,535

Every open port is a possible way in, so attackers scan for open ports first. Some ports get far more attention than others because the services behind them are common and often poorly protected.

Part 1: Scan with Nmap

Step 1.1: Open a terminal

  1. Open Terminal from the Applications button on the dock.

Step 1.2: Run Nmap

  1. Run nmap localhost to scan your own machine.

By default, Nmap scans the 1,000 most commonly used TCP ports.

Which TCP ports are open?

Ports 22, 23, and 631.

Describe the service that uses each open port.

Port 22, SSH: an encrypted protocol for logging in to and managing a computer remotely. Port 23, Telnet: remote command line access that sends everything, including passwords, as clear text. Port 631, IPP (Internet Printing Protocol): used by CUPS, the Common UNIX Printing System, so the computer can act as a print server.

Research the vulnerabilities associated with each of these open ports.

Answers vary. SSH (22) is a constant target of password guessing with default or common logins. Telnet (23) exposes everything in clear text, so attackers on the network can read credentials and sessions, and it is often used for man-in-the-middle attacks. CUPS (631) has had flaws that let an attacker run commands with the print service's privileges or crash the service (denial of service).

Step 1.3: Use administrative privileges with Nmap

  1. Scan the UDP ports: run sudo nmap -sU localhost. Enter the password password. (UDP scanning needs root; try it without sudo to see the message.) Linux commands are case sensitive: -sU is not the same as -su.

Which UDP ports are open?

Ports 631 and 5353. Nmap reports them as open|filtered, which means it got no reply and cannot tell whether the port is open or a firewall dropped the probe. For UDP, that usually means open.

What is the purpose of the UDP service on each port?

UDP 631 is IPP, used by CUPS to find and announce printers on the network. UDP 5353 is multicast DNS (mDNS), which lets computers find each other's names and services on a small network without a DNS server.

Research the vulnerabilities associated with these UDP ports.

Answers vary. An exposed CUPS service has had flaws that allowed denial of service and running code remotely. If mDNS on 5353 is reachable from the internet, attackers can query it to learn about the computer, and can spoof requests to flood a target in a reflection (denial of service) attack.

  1. Run nmap -sV localhost. The -sV option detects the version of each service, which you can use to look up known vulnerabilities.

Step 1.4: Read the SSH host keys

  1. Run nmap -A localhost. The -A option turns on version detection and a set of scripts built into Nmap.

What are the SSH host key fingerprints?

The ssh-hostkey section lists three: a 3072-bit RSA key, a 256-bit ECDSA key, and a 256-bit ED25519 key, each with its fingerprint (for example 3072 56:68:77:00:41:7f:50:17:5b:73:82:36:47:c4:bc:2d for RSA).

How could an attacker use this information?

Host keys are public, so knowing them does not let anyone log in. An attacker can use them to identify and fingerprint the server, to check whether it uses weak or outdated key types, and to recognize the same server across networks. The SSH version from the scan helps the attacker look for known vulnerabilities.

How do users protect themselves from an attacker pretending to be this server?

Verify the server's host key fingerprint the first time you connect, by comparing it with a fingerprint you got from the administrator through a separate trusted channel (out of band). After that, SSH warns you if the key ever changes, which can be a sign of a man-in-the-middle attack.

  1. Run man nmap to read the manual page and find more options.

Summary: commonly attacked ports

Many ports must be open for a computer to work, but the busiest ones should be watched closely.

  • TCP 21 (FTP): attackers try anonymous logins and use it to upload, download, change, or delete files and to move malicious code.
  • TCP 23 (Telnet): clear text means attackers can read credentials and data, plant backdoors, and carry out man-in-the-middle attacks.
  • 53 (DNS): attackers can hide data inside DNS traffic (DNS tunneling) to sneak it out of a network, because DNS is allowed almost everywhere.
  • TCP 80 (HTTP): web servers are a frequent target for injected scripts such as cross-site scripting (XSS), malicious uploads, and denial of service.
